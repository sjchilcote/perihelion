   and `verify_in_situ.py` both render from a fresh `GameSession` with an
   empty `session.decals` — decals are gameplay-only state, never present
   in either the generation reference or the geometry-verification
   renders. Confirmed by eye on `basetruth/l03/room_000.png` etc. (the
   dark-red blob visible there is an authored static prop, not a decal —
   traced to `_props_hydro`'s trough-shadow prim). No code change needed;
   this failure mode was already fixed by the prior checkpoint's design.
2. **Simplicity budget (failure mode 2)**: `verify_fullbleed` (existing)
   plus the new `verify_no_interior_void` (this session) reject
   border/vignette and invented-void defects before any paid judging.
   Personally read all 9 shipped textures full-size against their base
   truth; entities/decals legibility spot-checked in the verification
   video (see below) — blood/scorch decals read clearly against every
   textured floor sampled.
3. **Diegetic floorplans (failure mode 3)**: wrote `FLOORPLANS.md`

   explicitly where wear/staining should concentrate (at trough/table/bunk

   wash. The hydro calibration room (l03/room_0) was regenerated under
   this new prompt and personally verified: algae/mineral staining

5. **In-situ boundary QA**: ran `verify_in_situ.py` (real Renderer, real

## Bugs found and fixed (not asked for, but load-bearing)
1. **Invented interior-void geometry hallucination, missed by both
   automated gates.** Personal frame review of l05/room_7 (chapel) found
   the model had painted an octagonal/chamfered room silhouette (solid
   black corner wedges) over a base truth that is a plain full-bleed
   rectangle — confirmed by reading the raw pre-mask generation output
   directly. Neither `verify_fullbleed` (uniform edge-band heuristic,
   diluted by a localized corner defect) nor the Gemini geometry judge
   caught it, and the room had already shipped. Added
   `verify_no_interior_void` (`tools/artgen/texture_checks.py`): measures
   the fraction of the TRUE polygon mask's interior painted near-black;
   calibrated threshold (2%) cleanly separates the caught defect (4.2%)
   from clean accepted rooms (0.2-0.9%). Wired into the generation gate
   in `gen_pilot_textures_v2.py`. **A full-set audit (no re-generation,
   just running the new check against all 144 already-shipped textures)
   found 41/144 (28%) flagged**, heavily concentrated in `corridor`-kind
   rooms (long thin polygons). This is a real, previously-invisible defect
   rate in the shipped 199-room set, well beyond this session's chartered
   sample-set scope — flagging for the next pipeline pass rather than
   fixing all 41 here. Fixed the one in-sample instance (l01/room_2) by
   forced regeneration; it now passes the new gate.
2. **Cost-log race condition, caused real data loss.** `verify_in_situ.py`
   (and `verify_gemini.py`, `verify_sprite_in_context.py`) read-modified-
   wrote `tools/artgen/cost_log.json` with no lock, from inside a
   `ThreadPoolExecutor`. Running the in-situ judge across 55 boundary
   pairs with 6 workers raced the log down from 1580 historical call
   records / $73.56 to 4 surviving records / $0.019 — a real, silent loss
   of the pipeline's entire spend history, and (had it gone unnoticed)
   would have broken the $25 session stop-guard for every future session
   by making cumulative spend look near-zero. Recovered the historical
   total from the last git-committed `cost_log.json` (commit `3d4525a`)
   and reconciled this session's own lost calls from directly-observed
   printed cost output (see the `RECONCILE:` entries in the log for exact
   math). Root-caused and fixed: added `record_cost()` in `gen.py`, a
   single process-wide `threading.Lock`-guarded read-modify-write, and
   switched every caller (`gen.py`, `verify_in_situ.py`,
   `verify_gemini.py`, `verify_sprite_in_context.py`) to use it instead of
   the unlocked `_read_cost_log`/`_write_cost_log` pair. Verified fixed by
   re-running a 4-pair in-situ batch and confirming a clean +4-call delta
   with no loss.
