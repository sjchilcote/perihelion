## Bugs found and fixed (not asked for, but load-bearing)
1. **Invented interior-void geometry hallucination, missed by both
   automated gates.** Personal frame review of l05/polygon_7 (chapel) found
   the model had painted an octagonal/chamfered polygon silhouette (solid
   black corner wedges) over a base truth that is a plain full-bleed
   rectangle — confirmed by reading the raw pre-mask generation output
   directly. Neither `verify_fullbleed` (uniform edge-band heuristic,
   diluted by a localized corner defect) nor the Gemini geometry judge
   caught it, and the polygon had already shipped. Added
   `verify_no_interior_void` (`tools/artgen/texture_checks.py`): measures
   the fraction of the TRUE polygon mask's interior painted near-black;
   calibrated threshold (2%) cleanly separates the caught defect (4.2%)
   from clean accepted polygons (0.2-0.9%). Wired into the generation gate
   in `gen_pilot_textures_v2.py`. **A full-set audit (no re-generation,
   just running the new check against all 144 already-shipped textures)
   found 41/144 (28%) flagged**, heavily concentrated in `corridor`-kind
   polygons (long thin polygons). This is a real, previously-invisible defect
   rate in the shipped 199-polygon set, well beyond this session's chartered
   sample-set scope — flagging for the next pipeline pass rather than
   fixing all 41 here. Fixed the one in-sample instance (l01/polygon_2) by
   forced regeneration; it now passes the new gate.
2. **Cost-log race condition, caused real data loss.** `verify_in_situ.py`
   (and `verify_gemini.py`, `verify_sprite_in_context.py`) read-modified-
   wrote `tools/artgen/cost_log.json` with no lock, from inside a
   `ThreadPoolExecutor`. Running the in-situ judge across 55 boundary
   pairs with 6 workers raced the log down from 1580 historical call
   records / $73.56 to 4 surviving records / $0.019 — a real, silent loss
   of the pipeline's entire spend history, and (had it gone unnoticed)
   would have broken the $25 session stop-guard for every future session
   by making cumulative spend look near-zero. Recovered the historical
   total from the last git-committed `cost_log.json` (commit `3d4525a`)
   and reconciled this session's own lost calls from directly-observed
   printed cost output (see the `RECONCILE:` entries in the log for exact
   math). Root-caused and fixed: added `record_cost()` in `gen.py`, a
   single process-wide `threading.Lock`-guarded read-modify-write, and
   switched every caller (`gen.py`, `verify_in_situ.py`,
   `verify_gemini.py`, `verify_sprite_in_context.py`) to use it instead of
   the unlocked `_read_cost_log`/`_write_cost_log` pair. Verified fixed by
   re-running a 4-pair in-situ batch and confirming a clean +4-call delta
   with no loss.

# FIX ROUND (same day, PM session): props out of textures entirely

## Director corrections (mid-session, this round's brief)
1. "What's showing on screen still has baked in arrows."
2. "The props should not be baked in either. Please comprehend the
   concept of a texture." Labeled prop-to-paint substitution ("draw a
   hydroponics rack where this box is") is legitimate ONLY as a
   deliberate explicit mechanism — NOT implemented this round; nothing
   implicit.

## Root cause
`render.py` `_draw_world` draws `_draw_floor` then `_draw_detail`
UNCONDITIONALLY every frame, textured polygon or not. The base truth
(`polygon_basetruth.py`) included the full `_draw_detail` prop render, so
every AI texture was an ILLUSTRATION of scene content the engine already
draws live — chevron arrows ghosted visibly (thin line prims don't
self-occlude their baked echo); crates/consoles were redundant paint
under the live prims. A texture is the floor MATERIAL; props are objects
the game composites on top.

## Fixes (all at the source)
- `polygon_basetruth.py`: base truth is now `_draw_floor` ONLY — no
  `_draw_detail` call. All 199 base truths regenerated. `render.py`
  itself: net-zero diff.
- `pilot_texture_lib.py` `build_polygon_prompt`: guide described as
  floor-only; explicit prohibition on painting any crate/console/pipe/
  vent/arrow/valve/sign/discrete object; hydro + lab FLOORPLAN_NOTEs
  rewritten to give wear-bias positions in words (no guide prop shapes
  to point at anymore); neighbor-composite note now states a threshold
  is OPEN FLOOR (the model was painting hatch/door inserts where
  neighbor strips touch).
- `verify_gemini.py`: `geometry_ok` now rewards prop-free output and
  fails ANY invented object (was: "props must match base truth").

## Gate instruments re-validated on known-answer fixtures
With props removed, two programmatic gates turned out to have been
leaning on prop content for their signal:
- `verify_shape_conformance` REBUILT: the per-pixel energy-weighted mean
  conflated isotropic micro-texture (treadplate/scratches ≈ 22.5 deg
  uniform-spread mean) with oblique grids; it rejected personally-
  verified clean axis-aligned candidates at 16-20 deg. Replaced with the
  smoothed orientation-histogram PEAK per wall edge (structure
  concentration, which micro-texture cannot shift). Fixtures: f52 defect
  texture (old l07/polygon_7) 25.2 deg FAIL; clean candidates 0.5-1.0 deg
  PASS; tol 12.
- polygon-level `verify_no_repetition` RETIRED (kept for the material-swatch
  gate): measured ANTI-correlated with its target defect. The director-
  photographed arrow polygons measure peak_ratio 0.219 (would PASS — an
  arrow appearing twice is invisible to autocorrelation) while
  personally-verified clean prop-free candidates measure 0.24-0.49
  (rivet rows / plate pitch are legitimately periodic). No threshold
  separates the classes; the defect class scores LOWER. The arrow/sign
  defect is instead prevented at source (no props in base truth, prompt
  + judge prohibitions, signage-free materials).

## Noise + black-area audit (director's follow-up, same session)
Director: shipped polygons read "a little visually noisy" and still show
generator-introduced black; audit the prompts; consider entropy as the
instrument; prompts must ask for moderate detail / low visual noise.

Prompt audit findings:
- STYLE_LANGUAGE literally demanded "Hyper-detailed surface material:
  real wear, scuffing, grime, corrosion" -- the noise was specified, not
  emergent. Rewritten: MODERATE detail / LOW visual noise, large calm
  plate areas, sparse localized wear, "when in doubt render a panel
  PLAINER than the swatch", density explicitly LOWER than the material
  swatch (the swatch shows the material at its most weathered; the polygon
  floor lives under live props/decals/lighting).
- Black areas: the guide legend ("pure black = void outside the hull")
  gives the model license it kept over-applying (black margins, black
  beyond doorways, near-black burst motifs on l07/polygon_2: 7.5% of its
  floor under luminance 25). Added a BLACK LAW to STYLE_LANGUAGE: black
  appears ONLY exactly where the guide shows it (outside the
  silhouette); every pixel inside the silhouette is lit floor material.

Instrument findings (measured, 8 accepted polygons + kind swatches):
- Intensity ENTROPY does not discriminate: polygons 5.2-6.8 bits vs
  swatches 5.4-6.8 -- the approved style is entropy-rich, so an entropy
  threshold would pass noisy polygons and fail clean ones. Reported but
  not gated on.
- Mean Sobel gradient energy RELATIVE to the kind's approved swatch
  does: calm polygons 0.95-1.16x, the visibly noisy ones 1.35x
  (l07/polygon_6), 1.39x (l01/polygon_117), 1.76x (l07/polygon_2). New
  `verify_detail_budget` gate at 1.25x wired into the polygon loop; the
  three offenders force-regenerated under the new prompt + gate.

## Churn bug (director-caught): accepted polygons were re-rolled every run
Director: "are we applying textures to different, new polygons every pass?
... I see the same issues every time." Confirmed mechanically: the polygon
SET was fixed (same 11 sample keys), but --sample's pass 2 force-redid
EVERY polygon with an in-sample neighbor on EVERY invocation -- each run
silently replaced personally-verified accepted textures with fresh model
rolls, re-exposing the same failure modes on polygons that were already
done. The set churned instead of converging; that is exactly why the
same defects kept resurfacing across review rounds.
Fix: STICKY ACCEPTANCE in gen_pilot_textures_v2.py -- an accepted polygon
whose result already used a neighbor composite is final and is never
re-rolled; pass 2 only regenerates polygons not yet accepted-with-
conditioning. Repeated --sample runs are now idempotent.
